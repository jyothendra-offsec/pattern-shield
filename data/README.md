# Synthetic dataset card

## Source and purpose
dataset.csv is generated by the notebook's template generator. It contains inert request-like text for a quick, reproducible classification experiment. It is not captured traffic, CSIC, CIC, a Kaggle benchmark or production telemetry.

## Columns
| Column | Meaning |
|---|---|
| text | Original generated request-like text |
| label | benign, sqli or xss |
| split | train, val, test or challenge |
| group | Template identity; must not cross splits |
| normalized | Bounded URL/entity-decoded text used for tokenization and baseline |

## Counts after canonical deduplication
Train: 1,467 (467 benign, 500 SQLi, 500 XSS).
Validation: 360 (120 per class).
Test: 450 (150 per class).
Challenge: 300 (100 per class).
Total: 2,577.

The reduced benign training count follows duplicate removal.

## Generation
Method, endpoint and parameter name are sampled independently of label. Numeric/text substitutions and optional percent encoding create variants. Payload templates differ across partitions. Challenge subtypes include timing-style SQL strings and alternative HTML event contexts.

## Label semantics
Labels reflect the intended synthetic template. A SQLi/XSS-labeled string is attack-like; the dataset does not establish that any server processed or was vulnerable to it. Benign examples include technical discussion that can resemble malicious syntax.

## Leakage controls and remaining risks
The pipeline checks group partitioning and conflicting duplicate labels, and removes exact normalized duplicates. Similar grammar and shared generator design still create substantial dependence. Counts are balanced in evaluation, unlike many operational settings.

## Optional user CSV
Supply text,label,split,group. Assign related sessions, sources and payload families together before training. Every split must have every class. Document source, collection authorization, license, redaction, labeling, dates and split policy. Never include passwords, tokens, cookies or identifiable customer traffic.

The notebook enforces basic structural checks, not data rights, complete redaction, independent labeling or semantic near-duplicate separation.
